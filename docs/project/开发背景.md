# NucleaMind 项目背景说明

## 1. 项目背景

NucleaMind 基于开源项目 `nanobot` 进行二次开发。

原始 nanobot 是一个轻量级、开源、自托管的个人 AI Agent 框架，已经具备完整的通用 AI 助手能力，包括：

* Agent Runtime
* 大语言模型调用能力
* Tool Calling
* Memory 系统
* MCP 支持
* Chat Channel
* Automation
* Multi-Agent 相关能力
* Web UI 和各种集成能力

因此，NucleaMind 并不是从零开始构建一个 Agent，而是在 nanobot 已有成熟能力的基础上，探索一种不同的 Agent 架构方向。

当前项目的目标不是继续增加更多功能，而是重新设计 Agent 的核心边界。

---

# 2. 项目愿景

NucleaMind 的长期目标：

> 构建一个轻量、模块化、可扩展的 Agent Kernel，通过插件生态构建不同类型的个人 AI Agent。

核心思想：

**Agent 核心应该保持最小化，只负责最基础的智能体运行能力，而具体功能应该通过插件进行扩展。**

传统 AI 助手架构：

```
AI Assistant

 |
 +-- Agent Runtime
 +-- Memory
 +-- Telegram
 +-- Discord
 +-- Browser
 +-- Search
 +-- Workflow
 +-- Automation
 +-- Multi-Agent
```

这种模式的问题：

* 核心越来越复杂
* 功能和框架高度耦合
* 用户无法自由组合能力
* 第三方生态难以形成

NucleaMind 希望采用：

```
                 NucleaMind Kernel

                         |

              Plugin Runtime System

                         |

 ------------------------------------------------

 Channel     Memory     Tools     Workflow
 Plugin      Plugin     Plugin    Plugin

 Context     Model      Multi     Automation
 Plugin      Plugin     Agent     Plugin
```

核心保持稳定，能力通过扩展提供。

---

# 3. 项目核心理念

NucleaMind 的设计理念：

## 3.1 Kernel First

NucleaMind 不定位为一个完整 AI 助手产品，而定位为 Agent Kernel。

核心只提供：

* Agent 执行循环
* LLM 抽象层
* 消息系统
* Session 管理
* Context 构建接口
* Tool 注册机制
* Plugin Runtime
* 基础配置管理

核心不应该直接包含：

* Telegram
* Discord
* Slack
* Browser
* 特定数据库
* 特定 Memory 实现
* Workflow Engine
* Multi-Agent Framework
* Automation 系统

这些能力应该作为插件存在。

# 4. 从 nanobot 到 NucleaMind 的改造方向


目标：


这些能力不再属于核心，而属于可选扩展。

# 5. Plugin System 设计方向

插件系统是 NucleaMind 的核心能力之一。

插件应该不仅支持工具扩展，还应该支持 Agent Runtime 各个层面的扩展。

目标支持：

```
Plugin

 |
 + Tool Provider

 |
 + Channel Provider

 |
 + Memory Provider

 |
 + Context Provider

 |
 + Model Provider

 |
 + Workflow Provider

 |
 + Multi-Agent Provider

 |
 + Lifecycle Hooks
```

插件系统需要支持：

* 动态加载
* 生命周期管理
* 能力注册
* 配置管理
* 权限管理
* 依赖管理

NucleaMind 不会直接删除 nanobot 已有能力。

而是将已有能力逐步插件化。

例如：

原：

```
nanobot

Telegram
Discord
Memory
Browser
MCP
Automation

```

目标：

```

+

nucleamind-plugin-browser
```

---

# 7. Memory 架构方向

Memory 不应该是固定实现。

核心只定义 Memory Interface。

例如：

```
Memory Interface

        |

 -----------------------

File Memory

Vector Memory

Graph Memory

External Memory Service
```

NucleaMind 默认提供一个简单基础 Memory 插件，满足基础使用。

高级用户可以开发：

* 向量数据库 Memory
* 知识图谱 Memory
* 外部知识库 Memory
* 个性化长期记忆系统

---

# 8. Context 系统方向

Context 构建是 Agent 的核心能力之一。

NucleaMind 不希望将 Context 策略写死。

核心只提供 Context Interface。

例如：

```
Context Interface

        |

 ------------------

Basic Context Provider

RAG Context Provider

Knowledge Graph Context Provider

Personal Memory Context Provider
```

默认提供基础 Context 系统。

用户可以通过插件实现自己的：

* 上下文压缩策略
* 检索策略
* 长期记忆注入策略
* 个性化 Prompt 构建策略

`D51` 已把上下文压缩落成独立的 `COMPACTOR` 插件能力：Kernel 不内置摘要算法，也不会因
安装插件而自动启用。用户通过 `context.compactor` 显式选择策略；插件决定摘要内容和压缩
水位，Kernel 负责按完整请求触发、超时、写入前最终校验、持久化、重载与事件。插件失败
直接终止当前 Turn，不回退到旧的确定性硬裁剪。

插件的信任模型是：安装并启用即完全信任它在当前进程执行 Python 代码。Kernel 不维护插件
权限声明、授权账本或行为监控；`PluginContext` 资源门面只是统一的宿主服务。监听型能力由
插件启用与配置控制，更严格的隔离交给独立宿主、容器或部署环境。

* Slack

---

# 10. Multi-Agent 架构方向

Multi-Agent 不应该成为核心强绑定能力。

NucleaMind 核心只提供 Agent 扩展接口。

例如：

```
Basic Agent Runtime

        |

Agent Provider Interface

        |

Multi-Agent Plugin
```

不同用户可以实现不同 Multi-Agent 系统：

* Supervisor Agent
* Research Agent
* Coding Agent
* Debate Agent
* Workflow Agent

NucleaMind 不限制具体实现。

官方也可以提供默认 Multi-Agent 插件。

---

# 11. 生态兼容方向

NucleaMind 会研究并兼容已有 Agent 扩展生态。

重点参考：

## OpenClaw Plugin System

OpenClaw 已经拥有较完整的个人 AI 助手插件体系。

NucleaMind 不会简单复制 OpenClaw，而是设计兼容层：

```
OpenClaw Plugin

        |

OpenClaw Adapter

        |

NucleaMind Runtime
```

目标：

让已有 OpenClaw 插件能够运行在 NucleaMind 上。

---


# 12. 长期目标

NucleaMind 不希望成为另一个封闭 AI 助手。

长期目标：

> 成为一个开放、模块化的 Agent Runtime，让开发者可以通过组合插件快速构建不同类型的 AI Agent。

最终形态：

```
                 Agent Extension Ecosystem


          /              |              \


 OpenClaw Plugin    Other Agent Extension   Native Plugin


                    |

              NucleaMind Kernel
```

---

# 13. 开发原则

后续开发过程中遵循以下原则：

## 13.1 核心优先稳定

任何功能加入核心前，需要判断：

> 这是 Agent Runtime 必须能力，还是用户需求能力？

如果属于用户需求，应优先设计为插件。

---

## 13.2 接口优先于实现

不要直接绑定：

* 某个数据库
* 某个聊天平台
* 某个模型供应商
* 某个工作流框架

优先设计抽象接口。

---

## 13.3 机制优先于功能

核心负责提供：

* Extension Mechanism
* Lifecycle
* Registry
* Interface

而不是堆积具体功能。

---

# 14. 初始开发方向

当前阶段主要目标：

1. 分析 nanobot 当前架构。
2. 区分 Kernel 能力和 Feature 能力。
3. 将非核心能力抽离为官方插件。
4. 设计 NucleaMind Plugin Runtime。
5. 建立 Plugin SDK。
6. 实现官方插件集合。
7. 研究 OpenClaw 等生态兼容方案。
8. 逐步完善 Agent Extension Ecosystem。
